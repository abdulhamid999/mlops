# heatwave-mlops

Next-day heat-wave forecasting for Delhi, built end-to-end through four stages:
**ML → MLflow → MLOps → DevOps**.

- **ML** (Experiment 1): a Random Forest trained on 73 years of real IMD daily
  temperature data (1951–2024), with a heat-wave label built from IMD's own
  operational definition and a leakage-free, chronologically-validated
  next-day forecasting setup.
- **MLflow** (Experiment 2): 5 tracked hyperparameter/class-weighting
  configurations, compared on recall/precision (not just accuracy), with the
  selected model registered as `delhi-heatwave-nextday-rf` v1.
- **MLOps** (Experiment 3): the registered model served behind a Flask API
  (`/health`, `/predict`) with input validation and graceful degradation.
- **DevOps** (Experiment 4): containerized with Docker, tested with pytest,
  and checked automatically by GitHub Actions on every push.

## Project structure
```
heatwave-mlops/
├── app.py                    # Flask prediction service
├── train.py                  # reproduces model/ from raw data
├── save_model.py             # promotes an MLflow-registered model to a joblib file
├── data/
│   └── heatwave_data.csv     # real IMD daily data, Delhi, 1951-2024
├── model/                    # gitignored -- regenerated by train.py
├── tests/
│   └── test_app.py           # pytest suite (Flask test client, no server needed)
├── requirements.txt          # lean, for the serving image
├── requirements-dev.txt      # + mlflow, pytest, for training/CI
├── Dockerfile
├── .dockerignore
└── .github/workflows/ci.yml
```

## Run locally (no Docker)
```bash
pip install -r requirements-dev.txt
python train.py --data data/heatwave_data.csv   # produces model/
python -m pytest tests/ -v
python app.py                                    # serves on :8000
```

## Run with Docker
```bash
python train.py --data data/heatwave_data.csv   # model/ is gitignored, build it first
docker build -t heatwave-api:1.0 .
docker run -p 8000:8000 heatwave-api:1.0
curl http://localhost:8000/health
```

## Example request
```bash
curl -X POST http://localhost:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"date":"2024-06-09","max_temp":44.8,"min_temp":29.5,"rain":0.0,
       "recent_max_temps":[41.2,42.5,43.0,43.8,44.1,44.5,44.8]}'
```

## Push to your own GitHub
```bash
git remote add origin https://github.com/<your-username>/heatwave-mlops.git
git branch -M main
git push -u origin main
```
GitHub Actions will then run `.github/workflows/ci.yml` automatically on push
(its `docker-build` job needs a Docker-enabled runner, which GitHub provides
by default — no setup needed).

## Model performance (chronological holdout, 2011–2024)
| Metric | Value |
|---|---|
| Recall | 0.88 |
| Precision | 0.34 |
| F1 | 0.49 |

Selected deliberately for its recall/precision balance in Experiment 2 — see
that experiment's report for why the highest-accuracy configuration was
*not* chosen.

## MLflow tracking
Re-run the 5 tracked experiments and re-register the model with:
```bash
python mlflow_experiments.py   # see the Experiment 2 notebook for this script
mlflow ui --backend-store-uri sqlite:///mlflow.db   # browse runs at localhost:5000
```
